## Scelte da verificare

- `verify_once` controlla le tre librerie insieme a ogni primo ingresso; il core non usa ancora WCSLIB, quindi la verifica di WCSLIB passa dagli ingressi di LibRaw e CFITSIO e ogni futuro ingresso WCSLIB deve chiamarla (scritto in `third_party.hpp`).
- Ordine in `decode_raw_buffer`: `verify_once` prima di `check_process_tz`. Così il test di iniezione si ferma sulla verifica anche senza `TZ=UTC0`; con l'ordine opposto passerebbe per l'asserzione di TZ.
- File di test toccati dall'autore del codice (elenco in «Modifiche»): servono per mantenere eseguibili i test esistenti con le librerie nuove; l'agente dei test o il coordinatore li confermi. In particolare `raw_threads.cpp`: il controllo (c) non prova più i thread di libgomp ma quelli di `pthread_create`.
- `get_decoder_info` non passa dal gancio `libraw_return`: i test T-M3A-RAW-05 contano le sue chiamate (con il passaggio dal gancio, 3 test fallivano).
- LibRaw e WCSLIB sono compilate in-source: un cambio di opzioni richiede di cancellare `build/<preset>/third_party/<nome>` (limite dello strumento di mutazione).
- La prima esecuzione di `tools/check.sh` ha usato 11 job di build (tetto di `tools/cpu_cap.sh`) invece dei 4 chiesti; le esecuzioni successive 4.

## Limiti

- Nessuna delle tre fonti pubblica hash o firma: lo SHA-256 è quello del file scaricato via HTTPS il 30 ottobre 2026 (contratto §1, §5).
- Licenze di sistema: `libgcc_s` e `libstdc++` sono lette dal tag `gcc-16.1.0`, la versione installata è lo snapshot `16-20260322`; glibc da `COPYING.LESSERv2` del tag `glibc-2.43` (`COPYING.LIB` è un collegamento a quel file); i tag corrispondono alla versione upstream, non al pacchetto Debian.
